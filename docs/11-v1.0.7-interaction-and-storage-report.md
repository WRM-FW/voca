# Voca v1.0.7 — Interaction & Storage Report

Date: 2026-11-18. Windows-only (Android remains paused). Implements the
user-approved change review of 2026-11-18 (systematic UX evaluation of
v1.0.6), with emphasis on interaction. `schemaVersion` stays at 4; v1.0.0 ~
v1.0.6 archives load unchanged.

## What changed

### Storage (review items P-01/P-02/P-03)
- **Sparse persistence.** `getRecord()` materializes a default record for
  every rendered word, so one click after opening CET-4 persisted 383 KB /
  3,992 records. Saves now write only non-default records (a missing record
  already reads back as default). Measured after this change: the same click
  persists **644 bytes / 1 record**. A seeded v1.0.6 archive with 2,502
  records (2 real + 2,500 defaults) loads losslessly and is pruned to the 2
  real records on the next save; diagnostics now counts active records.
- **Debounced save + flush on exit.** `saveState()` coalesces writes over
  250 ms and `flushSaveState()` runs on `pagehide` / `visibilitychange`
  (hidden), so rapid row clicking no longer serializes the whole state per
  click and the session tail is not lost on close.
- **Corruption recovery.** A present-but-unparseable LocalStorage value is
  now treated like a missing one: the bad value is preserved under a
  `voca_offline_state_v1.corrupt.<timestamp>` key, the intact IndexedDB
  mirror is restored, LocalStorage is repaired on the next flush, and the
  user is told via toast. Previously corruption silently reset all progress
  while the mirror was never consulted. LocalStorage write failures
  (quota/blocked) now surface a toast advising a backup export instead of
  only `console.warn`. Backup exports use the same pruned state.

### Search (P-08)
- The learn view's empty state is split by cause: search-with-no-match
  (with the query named), all-mastered completion, and genuinely empty
  list. A fruitless search no longer shows the "🎉 all mastered" message.
- **Cross-book search**: the no-match state offers "在全部词库中搜索",
  which searches all books (plus custom words), lists up to 100 matches
  with book names, and clicking a result switches book/List, clears the
  search box and flashes the target row (expanding the list first when the
  word sits beyond the initial render limit).

### Keyboard & accessibility (P-09/P-13)
- **Escape closes the open modal** (dictionary / add-word / print /
  global-search), routed through each modal's own close button.
- `:focus-visible` focus ring, `prefers-reduced-motion` downgrade, and
  `aria-label`s on the icon-only row buttons (★ / ✕ / 📖) in the list and
  notebook templates.

### Header context (P-06)
- `switchTab` publishes `body[data-tab]`; the global header now hides the
  book/list/sort/language/view controls on the settings, data and notebook
  tabs, and hides sort/language/view on the plan tab (book/list stay). The
  theme button remains everywhere. This also returns vertical space on
  mobile, where the same header is used.

### Mobile portrait learn view (P-05)
- Under the mobile shell, the learn view's four stat cards become a compact
  single-row strip (headline numbers kept, sub-lines dropped on mobile
  only), the view-head subtitle and the desktop click-rule hint are hidden
  (the touch gesture hint remains), and toolbar spacing tightens. Measured
  on 390×844: the first word row moved from **~730 px to ~443 px**; the
  first two words are now on the first screen.

### Desktop narrow windows (P-04)
- New fine-pointer breakpoints (gated `(hover:hover) and (pointer:fine)`,
  the same convention as the existing desktop rules): at ≤900 px the
  sidebar collapses to a 68 px icon rail and the header wraps; at ≤620 px
  the stats grid goes two-up and selects are width-capped. Rule-level
  verification (the headless shell cannot emulate hover/pointer, so the
  rules were also measured ungated): at 500 px every header control is
  reachable and the main area is 432 px wide (was 244 px); at 390 px the
  main area is 322 px (was 134 px).

### First-use guidance (P-10)
- The first time a row click raises unfamiliarity, a one-time toast
  explains the contract ("点行 = 不会度 +1 并发音，右键/长按 −1，可在设置中
  切换点击行为"). The default click mode itself is unchanged.

## Not changed (per the review's explicit non-goals)
- Word-row / card information density (P-07/P-11, preference-class).
- Dictionary loading paths (pending real-device verification).
- The dual-engine storage architecture itself; click-mode defaults.

## Verification (headless Chromium, same harness as the review)
- Sparse save 644 B / 1 record; v1.0.6 fat-archive migration lossless +
  pruned; corruption → IndexedDB recovery toast + repaired LocalStorage +
  corrupt-value backup key; backup export carries `version: "1.0.7"` with
  pruned records (1,027 B in the test state).
- Global search: "ubiquitous" (absent from CET-4 List 1) → GRE result →
  click jumps book, flashes row, clears search. Esc closes the dictionary
  modal. Header controls hidden on settings, restored on learn.
- Mobile 390×844 first row at 443 px; spelling, cards, plan, notebook,
  data, settings and check-in smoke-tested with zero page errors.
- Not covered here (needs the real shell): WebView2 behaviour, speech,
  online-dictionary success rates, print output, and the hover/pointer
  media gate on a real mouse desktop.
