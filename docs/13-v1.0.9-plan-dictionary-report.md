## 2. WordReference 内嵌化（宿主抓取桥）

实测约束（2026-11-18 复测）：WordReference 返回 `X-Frame-Options: SAMEORIGIN`、CSP `frame-ancestors` 白名单、无 `Access-Control-Allow-Origin`，并有 Anubis 人机验证。页面自身既不能 iframe 内嵌、也不能 fetch 读取——这是站点与浏览器安全模型的硬限制，不是前端代码问题。

方案：给原生宿主（`src/windows/voca_host.c`）加抓取桥：
- 前端经 WebView2 消息通道发 `{voca:"dict-fetch", id, url}`；
- 宿主在词典 WebView（按需创建、默认隐藏）中顶层加载该 URL（顶层导航可通过 Anubis），NavigationCompleted 后每 500ms 用 ExecuteScript 探测 `#articleWRD table.WRD` 是否渲染完成（上限 30 次），命中后取整页 HTML 回传 `{voca:"dict-fetch-result", id, ok, html}`；
- 前端用既有 WordReference 解析器（并新增去除 `.tooltip` 的「SC / Simplified Chinese」噪声）解析后，在弹窗内与欧路同款面板渲染，不再自动打开独立窗口；
- 桥不可用/抓取失败时，弹窗内显示原因与「在词典窗口打开源页面」按钮（用户主动点击才开窗）。

验证：无头 Chromium 注入假宿主桥（回传 curl 实抓的 apologize 词条页 HTML 140,135 B），弹窗内成功渲染出「道歉 dào qiàn」「赔不是」等条目与例句，全程未调用 window.open。宿主 C 代码已交叉编译通过（见下）；宿主实机抓取行为待用户在 Windows 上确认（本机无法运行 Windows exe）。

## 3. 导出文件名

- 当前 List 双语表：`<词书显示名>_List_<n>.pdf/.html`（实测 `四级核心_List_1.pdf`）；默写卷追加「默写测试卷」；计划表为 `<词书显示名> 学习计划表`；生词本为 `生词本重难点强化手册`。
- 浏览器打印另存 PDF 同步改名（打印前临时设置 `document.title`，afterprint 恢复）。
- 去掉写死的 `_v1.0.6` 后缀；打印副标题改用词书显示名（原为内部 id 大写）。

## 4. 随机序列修复

根因：List 内「随机序列」用固定种子 `planShuffleSeed + listIndex + 7`，同一 List 每次打开顺序完全相同。改为会话级随机盐：启动时随机生成、用户每次重新选择「随机序列」时重掷；同一会话内渲染保持稳定。回归实测：两次重选随机，前 30 词顺序不同；且与初始序不同。

## 5. 计划系统重构

- 设置页新增「学习计划」卡：词书 select（选项与顶栏同步克隆）、学习天数输入（默认 75）、单词序列 select（默认随机序列）、生成按钮与当前计划摘要。
- 生成计划 = 写 `state.planConfig {bookId, learnDays, sortMode, seed, createdAt}` 并定格：List 数 = 学习天数，总周期 = 学习天数 + 15（+1/+2/+4/+7/+15 复习，标准表经 60 天计划逐格比对 75 天 × 6 列全等）。
- `buildListsForCurrentBook` 在有定格计划且词书一致时只用 planConfig 切分；学习页序列（sortSelect）只作用于当前 List 内部排序。回归实测：切换 List 内序列为字母序后，List 1 成员集合（149 词）不变。
- 顶栏 bookSelect 改为 disabled 并加说明 title；换词书只能去设置重新生成计划。文件/粘贴/JSON 导入不再自动切换当前词书（与 Agent 直写口径一致）。
- 计划页删除 List 个数输入、词序 select 与快捷 pills，改为当前计划摘要 + 「去设置生成/调整计划」按钮。
- 无 planConfig 时启动自动切到设置页并 toast 引导（存量用户升级同样引导一次，记录不动）。
- 顺带修复：`switchTab` 原定义在 bindEvents 内部，模块作用域的 generatePlanFromSettings 与启动引导调用时抛 ReferenceError——已提升为模块级函数。
