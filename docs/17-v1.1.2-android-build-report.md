# Voca v1.1.2 — Android 版构建报告

日期：2026-11-20。按用户要求基于 1.1.2 构建 Android 版，UI/交互用前端内置的移动端外壳。

## 1. 移动端 UI：前端早已内置，本次零改动启用

前端自带完整的移动外壳（`html.ui-mobile`，由 `<head>` 内联脚本按 pointer: coarse / 触摸能力自动开启）：底部六标签导航（背单词/计划表/训练/生词本/导词PDF/设置）、侧栏隐藏、顶栏控件重排为触摸友好的网格、计划表按天卡片、弹窗全屏化、词条行触摸反馈与长按手势提示。无头 Chromium 以 Pixel 8 参数（412×915、触摸、移动 UA）实测：ui-mobile 正确开启、底部导航 62px 可见且可切换、设置页与计划表页渲染为单列移动布局、零 pageerror。Android WebView 中 pointer: coarse 成立，该外壳自动生效，无需任何前端改版，桌面版不受影响。

## 2. Android 宿主（android/，手工流水线、无 Gradle）

- `MainActivity`（单文件）：WebView 加载 assets/index.html（即 Windows 版同一份组装产物），开启 JavaScript/DOM 存储；拦截 index.html 请求并在 `<head>` 后注入 `bridge.js`。
- `bridge.js` 复刻 WebView2 的 `window.chrome.webview` 通道（postMessage/addEventListener + 原生侧 `__VOCA_DELIVER__` 回投），前端的词典协议零改动复用：dict-show/dict-rect/dict-hide 由第二个 WebView 按页面给的 CSS px×dpr 定位叠加（与 Windows 宿主同一机制），dict-shown 回执；dict-fetch 由隐藏 WebView 抓取回传；window.open 的词典窗口走全屏叠加 + 关闭条并回执 dict-window。
- 导出下载：WebView 保存不了 blob: 下载，bridge.js 拦截 a[download] 的点击（含程序化 .click()，已实测 detached anchor 的情形）转交原生侧，写入系统「下载」目录（MediaStore）；导入文件走系统文件选择器（onShowFileChooser）。
- 系统返回键：叠加层打开时先关叠加（并同步关闭页面词典弹窗），其次 WebView 后退，最后退出。

## 3. 构建与验证

- 工具链：OpenJDK 17 + Android SDK platform 34 / build-tools 34.0.0（在本机放在 ~/workspace/tools/android-sdk；sdkmanager 在本机代理下隧道失败，platform 与 build-tools 改用官方 zip 直装，见 TOOLS.md）。流水线：aapt2 compile/link → javac → d8 → zipalign → apksigner（`android/build_apk.sh` 一键）。
- 产物：Voca_v1.1.2.apk，包名 com.voca.app，versionCode 112 / versionName 1.1.2，minSdk 29（Android 10+）、targetSdk 34，仅 INTERNET 一个权限；签名证书 CN=Voca（密钥库在仓库外 ~/workspace/voca-v106/android-signing/，务必保留，后续版本同钥才能覆盖更新）。
- 模拟验证（无头 Chromium + 模拟原生桥，与真机相同的注入方式）：通道安装成功、零 pageerror；点 WordReference 后页面发出 dict-show、收到 dict-shown 回执并显示「已在弹窗内打开原页面」；备份 JSON 导出被正确转交原生保存（文件名 voca_backup_v1.1.2_日期.json）；欧路路径与桌面一致（页内抓取，失败回退本地词库）。
