# Voca v1.1.1 — 初始序列修复与下拉/滚动条现代化报告

日期：2026-11-18。按用户实机反馈四点开发。

## 1. 「初始序列不是真正的初始序列」——已定位并修复

复现（无头）：生成随机计划（默认）后到学习页选「初始序列」，List 1 前 12 词为 evolution / world / precaution / range / dot…，是切分时的乱序，不是词书原序。

根因：`getSortedActiveWords` 对 intraSort 只处理 az / random / hard_first 三个分支，`initial` 没有分支、直接按原样返回——即返回「计划切分顺序」。计划按初始切分时两者恰好一致（所以 1.0.9 的初始计划探针没暴露），计划按随机切分时「初始序列」就成了乱序，等于软件把真正的初始序列忘了。

修复：新增 initial 分支，按词条在词书中的原始序号 `w.seq` 升序排序。验证：以词库 payload 的 bookMap 为 ground truth，随机切分的 30 天计划下，List 1 全部 149 词在初始序列下的序号严格单调递增（成员集合与 az 下一致）。说明：计划层面的切分顺序仍由设置里的计划序列决定；List 内「初始序列」现在恒为词书原序。

## 3. 选择框现代化（自定义下拉）

原生 select 的弹出层由操作系统渲染：样式不受应用主题控制、列表粗大、自带粗滚动条、窄窗口下还会溢出（用户截图 4）。改造：

- 全部 `ctrl-select`（学习页序列、设置页计划词书/序列、List 选择、计划天数选择、生词本排序、训练词源、设置的口音/主题/字号/音标四个选择）换成自定义下拉：圆角按钮实时镜像当前值，菜单为卡片式（主题色、圆角、阴影、当前项打勾、最大高度 264px + 细滚动条、靠近右缘自动右对齐、点外/Esc 关闭）。
- 原生 select 隐藏保留在 DOM 中作值存储（`.cd-native`），既有 change 处理、程序化赋值（refreshAllViews 统一 re-sync 标签）、选项动态重建（MutationObserver 监听 childList 后重建菜单）全部照旧工作。顶栏已禁用的词书显示框不改。
- 无头验证：原生 select 带 cd-native 类、按钮标签与值同步、点开菜单、点选项后 select 值与状态正确变更且菜单关闭。

## 4. 滚动条现代化

## 5. 当日后续（版本仍 1.1.1）：初始序列的真正修复 + 打卡自动前进

用户实机反馈：随机切分的计划下，List 内选「初始序列」后 List 1 仍不从词书第一个词开始——第 1 节的组内排序只能把随机组内部按原序排好，组本身还是随机组。用户要的是「真正的初始序列」。

修复：`ensureBookOrderSplit()`——List 内选「初始序列」时，若冻结切分不是词书原序（planConfig.sortMode ≠ initial，或旧存档 planOrderMode ≠ sequence），先把切分本身改回词书原序再渲染：List 数与艾宾浩斯排期不变；单词记录按 wid、打卡按 List 号键存，均不受影响；设置页的计划摘要同步刷新，并有 toast 明示已重新分组。切分已是原序时行为与第 1 节一致。无头实测（用户同款场景：80 天随机计划）：选初始序列前 List 1 首词为随机词，选后 List 1 与词库 payload 前 56 词逐词一致（plastic 起），planConfig.sortMode 持久化为 initial。

打卡自动前进：`btnCheckinCurrentList` 打卡后，若还有下一组则 currentListIndex 前进一组；若是最后一组，则 planActiveDay +1 并跳到该天排期中的第一个 List（新学优先，否则最早的复习组），toast 注明去向，页面回滚顶部。无头实测：List 1 打卡后显示 List 2；最后一组打卡后 planActiveDay 1→2 且定位到 Day 2 的新学 List 2。regress111 / regress108 继续零错误。

发布处理：版本号不变，GitHub Release v1.1.1 的两个 zip 资产与说明原地替换/更新，仓库 index.html 同步更新。

## 6. 当日后续之二（版本仍 1.1.1）：打卡前进改为计划表阅读顺序

用户以艾宾浩斯计划表截图澄清：「从上到下、从左到右」——即按天推进、天内按 记忆 → 复习1(+1) → 复习2(+2) → 复习3(+4) → 复习4(+7) → 复习5(+15) 的列序前进，而不是 List 序号 +1（第 5 节的初版实现）。例如 Day 2 的新学 List 2 打卡后应进入复习 List 1，而不是 List 3。

实现：`getDayTasksInOrder`（某天任务 = newLists ++ revCols 依次展开）+ `findNextTaskInTable`（在全表线性序中找当前格的下一格，跨天取下一天首格；当前 List 不在本天任务中时向后找它下一次出现的格）。打卡后设置 planActiveDay 与 currentListIndex 并 toast「已自动进入 Day X · List Y」。配套：计划表 chip 增加 data-day，点击跳转时同步 planActiveDay，保证位置追踪一致。

无头实测（regress111c，80 天计划）：Day 2 打卡 List 2 → List 1（同日复习1），再打卡 → Day 3 List 3；Day 5 依次 5→4→3→1 → Day 6 List 6；Day 8 表内 chip 点击后 planActiveDay=8。均与用户截图的表格逐格一致；regress111/111b/108 继续零错误。Release 资产同版本再次原地替换。
